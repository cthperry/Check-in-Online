# 手機打卡功能規劃與驗收

## 首版範圍

目的是讓員工快速記錄上、下班，並能下載可核對的班次明細。手機首頁只顯示當前身分、打卡按鈕、時間和最近一個班次。紀錄頁提供日期範圍、查詢與 Excel 匯出。定位、排班、休假與薪資核算均未納入首版。

| 情境 | 目前處理方式 |
| --- | --- |
| 身分辨識 | 由管理人員開通帳號。伺服器依登入階段辨識員工。 |
| 自己的手機 | 預設保持登入 30 天，到期需重新登入。重設密碼或停用帳號時撤銷所有裝置的登入階段。 |
| 共用裝置 | 取消勾選保持登入，改用工作階段 Cookie，伺服器於 12 小時後到期。交接時點選登出。 |
| 時間與跨日 | 打卡時間由伺服器產生，畫面與 Excel 顯示台灣時間。跨午夜、跨月班次歸入上班日。 |
| 重複或同時打卡 | 每次提交含獨立識別碼與狀態版本。資料庫交易保留第一個有效動作。相同要求重送會回傳原時間。 |
| 班次規則 | 同一人同時僅能有一筆未下班。結束後可在同一天再次上班。 |
| 斷網或逾時 | 僅伺服器成功回覆後才顯示打卡成功。連線恢復先讀取最新狀態，必要時再由員工送出。 |
| 漏打下班 | 紀錄標示「待下班」。經手人可從受管主機補登，保留原欄位、新時間、原因與經手人。 |
| 匯出 | 員工僅能查自己；管理員可切換全體。每次可查最多 366 天。匯出含所有符合條件的列與該範圍的補登紀錄。 |
| 在班時數 | 以兩次打卡相差時間計算。未下班時留白。未扣休息時間，正式計薪應另訂規則。 |

## 上線前要決定

1. 指定可匯出全體名單的人員及漏卡核准人。現版管理員可讀全公司，若需依部門分權，應先補上部門欄位與資料範圍。
2. 選定出勤資料、匯出檔與備份的保存期限，以及備份保管人。登入事件採 90 天滾動清理，於登入操作時執行。
3. 確認完全漏打上班的申報方式。現版提供補登下班指令；補登整個班次與員工自助申請可列下一版。
4. 確認手機遺失的通報窗口。可由管理人員重設密碼，撤銷該帳號所有裝置的登入。
5. 確認夜班歸屬日。若月末需要按日拆分時數，應新增報表規則，並保留原始上下班時間。

## 驗收方式

- 使用兩個獨立瀏覽器登入同一帳號，同時上班打卡，資料庫只能有一個開啟的班次。
- 記住登入後關閉瀏覽器再開啟，確認仍帶入原員工。登出或帳號停用後，舊工作階段應失效。
- 用跨月案例測試月底上班、次月下班，確認整筆出現在上班月，工時計算正確。
- 分別以員工及管理員匯出，使用 Excel 開啟並核對姓名、日期、跨日時間、未下班、補登附表。
- 使用 iOS Safari 與 Android Chrome 實機測試鍵盤、點擊、重開瀏覽器與下載檔案。
